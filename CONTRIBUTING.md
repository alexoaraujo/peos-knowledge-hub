# Contribuindo com o PEOS Knowledge Hub

1. Crie uma issue indicando demanda, objetivo e evidência.
2. Utilize IDs permanentes e preserve namespaces (`0001`, `BPD-001`, `PMU-001`, `WF-001`).
3. Documente fonte e hash de cada ficha/contrato, impacto e versionamento.
4. Inclua testes de regressão, riscos e rollback quando aplicável.
5. Abra uma PR; não faça push forçado para `main`.
6. Aguarde CI no SHA publicado e revisão independente para gates sensíveis.

**Sem segredos, dados pessoais privados ou execução externa não autorizada.**
Conteúdo editorial `PROPOSED` não é considerado aprovado automaticamente.
Licenciamento do conteúdo anterior à versão do Hub permanece sujeito a revisão (issue #2).
